# UE Node Nexus 项目维护

目标是减少同类缺陷的产生条件和真实使用成本。issue 是发现契约缺口的证据；交付应修正产生错误的规则，并覆盖同一规则的其他表现。

所有路径以仓库根目录为基准。本技能服从当前用户任务与 AGENTS；它不授予关闭用户工程、丢弃修改、安装或推送的新权限。

## 先理解维护对象

先看工作区结构、git 状态和 release/DEVELOPMENT.md。本地存在 .high-value-information 时，从 index.md、current.md 读取当前事实；架构审查记录包含建议，历史文档里的“当前版本”和授权按日期解释。

区分三份实际状态：仓库源码、安装目录文件、进程已加载的 Python/DLL。先核对差异，保留其他会话的改动，将已验证的安装补丁回迁到源码后统一构建。

现有结构：

```text
src/ue_node_nexus_mcp/
├─ facade / registry / tools       MCP 入口与操作契约
├─ transcode                       文本、schema、候选、diff、发布与历史
├─ instances / tasks               进程、任务与生命周期
└─ safety / diagnostics            验证、诊断和证据
Plugins/
├─ UeNodeNexusBridge               Guard、Core 与原生资产操作
└─ UeNodeNexusVfxBridge            Niagara 原生领域操作
tests/
├─ contracts / transcode / instances / safety
├─ live / stress                  实际 UE 与连续编辑
└─ compile_check                  原生构建及安装核验
```

## 不改变的设计判断

- UE 原生接口负责引擎有效语义、对象生命周期和编译结果；Python 负责编辑意图、文本、编排及证据。
- .nexus 仅承诺其能表达和验证的子集。反射中可见的属性，不自动等于能安全编辑的属性。
- 作者声明、反射类型契约、物理绑定、派生状态分别处理。候选接口变化时，旧物理 pin 和旧 schema 不能覆盖新声明。
- 新增能力优先复用原生领域操作与已有契约。避免在 Python 再实现一套 Niagara 默认模式、引脚分配或 Blueprint 编译规则。
- 收缩全面镜像与通用语义 VCS 的默认职责是架构方向。现有工作区、历史、恢复和协作功能仍有效；普通修复不擅自删除它们，迁移须处于任务范围并保留历史可读性。

## 接到 issue 后的决策

先归类，再沿实际依赖定位产生端：

| 类别 | 首先核查 | 修复应落在哪里 |
| --- | --- | --- |
| 调用方输入/真实能力边界 | 请求是否违反已声明契约，能力是否准确公开 | 产生歧义的 schema、诊断或调用输入；有意不支持的能力明确报告 |
| 跨层契约不一致 | 文本可写、planner 可生成、native 可执行是否一致 | 真正提供能力或类型事实的生产端，消费者复用同一事实 |
| 语义解释偏差 | 默认/显式/重置、Local/Link/RI、静态类型、生成对象 | 原生语义适配与共享类型契约，覆盖相邻类型和存储入口 |
| 生命周期/时序 | accepted、applied、completing、completed、退出是否混淆 | 状态所有者及交接边界；保留结果未知和幂等恢复 |
| 部署/版本偏差 | 源码、构建记录、安装文件、已载 DLL 是否同一版本 | 正式构建安装链，确定的身份错误提前拒绝 |
| 效率退化 | 时间花在枚举、导出、比较、锁、复制还是启动/退出 | 缩小真实工作集合、复用有效描述、减少往返；测量后下结论 |

每个修复先写清：触发条件 → 产生操作 → 错误状态 → 用户症状；明确违反的契约及其权威来源。用 auto-index 查定义、引用和已有实现，避免只搜索报错字符串。

保留原始失败输入、版本、日志和回执。有可运行测试缝隙时，先看到原行为失败，再改产生端。一次静态推断不能代替真实边界观测。

随后检查**同一机制**的调用链：例如同一类型的 pin/store/Python 往返、同一签名的本地/跨资产/继承调用、同一状态的缓存/发现/重启路径。将这些变体变成契约回归，不无界扫描无关模块。

如果同类问题反复出现，重新判断谁应该拥有这项规则，合并重复语义或修正协议边界。禁止用资产名、某个字段名或当前案例的固定数值掩盖错误抽象；领域特例只能来自明确的 UE 契约。

## 检查应减少错误和成本

- 将离线可确定的输入、能力、删除选项和安装身份检查放在昂贵导出、复制、启动之前。
- 历史清洁描述与当前写入证据分开。磁盘 hash/dirty 不足以证明内存 revision；编译可能重建依赖而不改变它们。
- 实际写入目标与依赖必须取得当前证据；不得靠关闭 revision、读回或编译校验让失败消失。
- 验证作者实际写入的成员和必要引擎不变量。结构体 ImportText 的展开需要原生 value_schema；遗漏成员不等于要求清零。
- 批处理必须有整组依赖语义。逐项成功不等于整组保存后可冷加载，迁移期间不能提前删除后续成员需要的重定向。
- 保持明确的成功层次：接受请求、应用、编译有效、保存、冷加载、运行验收分别证明。Niagara 编译等待结束不等于可运行。
- 隔离是有成本的验证能力，当前默认 off，auto/always 按调用选项选择；维护时核对实际实现，避免指南和默认行为分叉。
- 错误摘要保留首个产生端原因、资产/字段/步骤和工件入口。大 checkpoint 放持久工件；未知结果先查回执，避免重放写入。

## 验证按变更选择

阅读 [验证与交付矩阵](references/verification.md)，选择能穿过本次失效边界的最小充分集合。

FakeUe 只证明其模拟的协议行为，未知动词必须失败。Python 与 native 各自全绿不能替代真实请求跨层执行；独立 oracle 应读取原生对象/API或执行函数，不能只比较两次产品导出。

值、签名、模块顺序、迁移和恢复变更，要覆盖连续状态变换、合法控制组及拒绝不修改状态。保留 seed 和物化轨迹；冷重启必须结束旧进程后重读磁盘，缓存 no-op 只是辅助断言。

范围明确的小改动不强制整套压力、完整工程复制或重复安装。出现新改动、失败或未覆盖的边界才扩测；通过后继续交付。

## 收口与维护记录

变更后检查死代码、嵌套、跨项目引用和模块职责；静态工具的动态入口误报需要用调用证据说明。

记录修复的**规则与不变量**、之前为什么漏测、增加了哪条跨层证据、实际性能成本和验证边界。issue 原文按项目约定编号归档，长期经验合入 HVI 主题，当前入口只指最终回执。

涉及安装时，从真实输入生成身份，构建、核对 DLL、安装，再冷启动核验实际加载路径。Python 逻辑变更不无故重编 native；源码提交本身不需要为了改变 commit 标签重建相同内容。

推送遵循当次授权和发布范围，只提交必要源码、可复用测试与文档；本地工程、日志、checkpoint、私有 HVI 和凭据留在本地。
